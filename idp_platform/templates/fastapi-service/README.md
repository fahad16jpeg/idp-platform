# __PROJECT_NAME__

FastAPI service generated by the `platform` CLI, with Docker, Terraform (Azure
Container Apps), GitHub Actions CI/CD, tests and monitoring wired in.

## Endpoints

| Path | Purpose |
| --- | --- |
| `GET /health` | Liveness: the process is up (startup and liveness probes) |
| `GET /ready` | Readiness: dependencies are reachable; returns 503 otherwise |
| `GET /info` | Name, version, deployed commit, environment, uptime |
| `GET /metrics` | Prometheus metrics, labelled by route template |
| `/api/v1/items` | Example CRUD resource (`GET`, `POST`, `GET/PUT/DELETE /{id}`) |
| `GET /docs` | Interactive API docs |

## Run locally

```bash
python -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install -r requirements-dev.txt

pytest                             # tests
ruff check .                       # lint
uvicorn app.main:app --reload      # http://localhost:8000/docs
```

Or with Docker (hot reload included):

```bash
cp .env.example .env               # optional local settings
docker compose up --build
```

### Configuration

Settings are environment variables prefixed with `APP_` (see `app/config.py`):

| Variable | Default | Notes |
| --- | --- | --- |
| `APP_ENVIRONMENT` | `development` | Set to `dev` / `prod` by Terraform |
| `APP_LOG_LEVEL` | `INFO` | |
| `APP_LOG_FORMAT` | `json` | `json` for Azure, `text` for reading locally |
| `APP_CORS_ORIGINS` | `[]` | JSON list; empty disables CORS |
| `APPLICATIONINSIGHTS_CONNECTION_STRING` | unset | Enables telemetry export; injected by Terraform |

Add a readiness check for each dependency you introduce:

```python
from app.routers.health import register_readiness_check
register_readiness_check("database", lambda: db.ping())
```

## Infrastructure

`terraform/` creates, in one resource group: Container Registry, Log Analytics,
Application Insights, a Container Apps environment and the Container App (pulling
images with a managed identity, no registry passwords), plus alerts.

State is stored remotely in Azure Storage, so CI and your machine always agree on
what exists.

## First-time deployment setup

1. **Create the GitHub repo** (empty: no README or .gitignore) and push:

   ```bash
   git remote add origin https://github.com/<you>/__PROJECT_NAME__.git
   git push -u origin main
   ```

   The first pipeline run will stop at "Check repository variables". That's expected.

2. **Bootstrap Azure** once. Needs the Azure CLI, signed in as a subscription Owner.
   On Windows, run it from Git Bash, WSL or Azure Cloud Shell.

   ```bash
   az login
   ./scripts/bootstrap-azure.sh <you>/__PROJECT_NAME__
   ```

   It creates the Terraform state storage and an identity GitHub logs in as via
   OIDC (nothing secret to store), and sets the repository variables if the
   GitHub CLI (`gh`) is logged in; otherwise it prints them for you to add.

3. **Optional:** add variable `ALERT_EMAIL` (alert notifications) and secret
   `ALERT_WEBHOOK_URL` (Slack/Teams message when a deployment fails).

4. **Re-run the pipeline** (Actions > pipeline > Run workflow) or push a commit.

## CI/CD

| Workflow | Runs on | Does |
| --- | --- | --- |
| `test.yml` | pull requests, and as stage 1 of the pipeline | ruff, pytest, `terraform fmt`/`validate`, Docker build check |
| `build.yml` | pipeline stage 2 | build image, Trivy scan (fails on fixable HIGH/CRITICAL), push to ACR tagged with the commit SHA |
| `deploy.yml` | pipeline stage 3, or manually | `terraform plan` + `apply` with the new image, then waits until `/ready` passes and `/info` reports the new commit |
| `pipeline.yml` | push to `main` | chains the three: each stage only runs if the previous one passed |

**Rollback:** Actions > deploy > Run workflow, and enter an earlier image
(`<acr>.azurecr.io/__PROJECT_NAME__:<older-sha>`).

**Local Terraform:** copy `terraform/backend.hcl.example` to `backend.hcl` and
`terraform.tfvars.example` to `terraform.tfvars`, fill them in, then:

```bash
cd terraform
terraform init -backend-config=backend.hcl
terraform plan
```

## Monitoring

- **Logs:** JSON lines to stdout, collected into Log Analytics. Example query:

  ```kusto
  ContainerAppConsoleLogs_CL
  | where ContainerAppName_s == "ca-__PROJECT_NAME__-dev"
  | extend log = parse_json(Log_s)
  | where tostring(log.level) == "ERROR"
  | project TimeGenerated, log.message, log.route, log.status_code
  ```

- **Telemetry:** requests, dependencies, exceptions and logs go to Application
  Insights (Azure Portal > Application Insights > `appi-__PROJECT_NAME__-dev`).
- **Metrics:** `/metrics` for Prometheus-compatible scrapers.
- **Alerts:** no running replicas, repeated restarts, failed requests, and failed
  Container App deployments. The deploy workflow also fails and notifies when a
  new revision doesn't become healthy.
